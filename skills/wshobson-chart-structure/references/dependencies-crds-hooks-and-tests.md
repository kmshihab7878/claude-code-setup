# Dependencies, CRDs, Hooks, And Tests

Purpose: detailed reference for chart dependencies, generated lockfiles, CRDs, hook lifecycles, and chart tests.

## Declaring Dependencies

```yaml
dependencies:
  - name: postgresql
    version: "12.0.0"
    repository: "https://charts.bitnami.com/bitnami"
    condition: postgresql.enabled
    tags:
      - database
    import-values:
      - child: database
        parent: database
    alias: db
```

## Managing Dependencies

```bash
helm dependency update
helm dependency list
helm dependency build
```

## Chart.lock

Generated by `helm dependency update`:

```yaml
dependencies:
  - name: postgresql
    repository: https://charts.bitnami.com/bitnami
    version: 12.0.0
digest: sha256:abcd1234...
generated: "2024-01-01T00:00:00Z"
```

Treat changes to `Chart.lock` as supply-chain changes and review them before commit.

## Custom Resource Definitions

Place CRDs in `crds/`:

```text
crds/
├── my-app-crd.yaml
└── another-crd.yaml
```

Important CRD notes:

- CRDs are installed before templates.
- CRDs are not templated with `{{ }}` syntax.
- CRDs are not upgraded or deleted with the chart.
- Use `helm install --skip-crds` only when the operator explicitly wants to skip CRD installation.

## Chart Tests

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: "{{ include "my-app.fullname" . }}-test-connection"
  annotations:
    "helm.sh/hook": test
    "helm.sh/hook-delete-policy": before-hook-creation,hook-succeeded
spec:
  containers:
    - name: wget
      image: busybox
      command: ["wget"]
      args: ["{{ include "my-app.fullname" . }}:{{ .Values.service.port }}"]
  restartPolicy: Never
```

Run tests only against an approved target release:

```bash
helm test my-release
helm test my-release --logs
```

## Hooks

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: {{ include "my-app.fullname" . }}-migration
  annotations:
    "helm.sh/hook": pre-upgrade,pre-install
    "helm.sh/hook-weight": "-5"
    "helm.sh/hook-delete-policy": before-hook-creation,hook-succeeded
```

Hook types:

- `pre-install`: before templates are rendered.
- `post-install`: after all resources are loaded.
- `pre-delete`: before any resources are deleted.
- `post-delete`: after all resources are deleted.
- `pre-upgrade`: before upgrade.
- `post-upgrade`: after upgrade.
- `pre-rollback`: before rollback.
- `post-rollback`: after rollback.
- `test`: run with `helm test`.

Hook weights control execution order. Lower values run first.

Hook deletion policies:

- `before-hook-creation`: delete previous hook before new one.
- `hook-succeeded`: delete after successful execution.
- `hook-failed`: delete if hook fails.
