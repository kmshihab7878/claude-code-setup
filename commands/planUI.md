# /planUI — CoreMind UI Pipeline

Specialization of `/plan` for UI and design work. Orchestrates the UI surface (skills, agents, MCPs, sub-commands) around an 8-stage design pipeline.

> **When to use** — `/planUI` for pure UI/design tasks; `/plan` when UI is one piece of a cross-domain task; `/ultraplan` for enterprise-scale cross-system UI with governance requirements.

References: [`agents/REGISTRY.md`](../agents/REGISTRY.md) (UI agents), [`docs/INVENTORY.md`](../docs/INVENTORY.md) (live counts), [`skills/coremind-core/SKILL.md`](../skills/coremind-core/SKILL.md), `skills/hue/`, `skills/interface-design/`, `skills/react-bits/`.

## The pipeline — 8 stages

### Stage 1: BRIEF — understand the human and the job

Answer in concrete terms before touching files:

- **Who is this human?** Specifics. A teacher at 7am with coffee. A developer debugging at midnight.
- **What verb must they accomplish?** "Grade submissions." "Find the broken deployment." Not "use the dashboard."
- **What should this feel like?** Words with meaning — *"warm like a notebook"*, *"cold like a terminal"*, *"dense like a trading floor"*. Not "clean" or "modern."

If you cannot answer these, stop and ask. **Do not guess. Do not default.**

**Surface type** — narrow the route:

| Surface | Primary skill | Avoid |
|---------|---------------|-------|
| Dashboard / admin / tool | `interface-design` | heavy `react-bits` backgrounds |
| Marketing / landing / hero | `impeccable-design` + `react-bits` | over-dense data UI |
| Design-system generation | `ui-design-system` or `hue` | ad-hoc tokens |
| Brand documentation / application | `brand-guidelines` + brand child skill | generic Tailwind |
| Reference extraction | `design-inspector` or `clone-website` | guessing at tokens |
| Video UI | `video-ui-patterns` + `remotion-animation` | web-oriented libs |

### Stage 2: ROUTE — pick the directional path

Pick before doing anything else.

**A) Brand-first** — user has or wants a brand identity.
```
hue → brand child skill → /interface-design-init → impeccable-audit → impeccable-polish
```

**B) System-first** — constraints (colors, type, spacing) but no formal brand.
```
ui-design-system → /interface-design-init → react-bits (cherry-pick) → impeccable-audit → impeccable-polish
```

**C) Component-first** — specific pattern, page, or interaction.
```
react-bits OR impeccable-design → responsive-design + framer-motion-patterns → baseline-ui → impeccable-polish
```

### Stage 3: DIRECTION — establish the feel before code

State the intent and technical approach:

```
Intent:    [who, what verb, how it should feel]
Palette:   [foundation + accent — WHY these colors fit]
Depth:     [borders / subtle shadows / layered — WHY]
Surfaces:  [elevation scale — WHY this temperature]
Typography:[typeface choice — WHY it fits]
Spacing:   [4px / 6px / 8px]
Motion:    [restrained / playful / physics-heavy — WHY]
Hero preset (marketing only): [luminous-on-gradient | device-on-mesh | sculptural-field | typographic-hero]
```

**Every choice must be explainable.** "It's common" or "it works" means you defaulted, not chose.

**The test**: if another AI given a similar prompt would produce the same output, you have failed. The interface must emerge from THIS user, THIS problem, THIS intent.

Hue example brands live in `~/.claude/skills/hue/examples/` for reference inspiration (`atlas`, `velvet`, `halcyon`, others).

### Stage 4: SYSTEM — generate or load tokens

- **Brand-first** → invoke `hue` ("make a design skill from <brand url / name / screenshot>"). Hue writes `~/.claude/skills/<brand>/` with tokens + components + hero stage + icon kit.
- **System-first** → invoke `ui-design-system` (tokens, modular type scale, 4pt/8pt spacing grid, component architecture, dev handoff: CSS vars, SCSS, Tailwind config).
- **Component-first** → skip to Stage 5 with inferred tokens.

Token taxonomy reference: `~/.claude/skills/hue/references/tokens-template.md` — neutral + brand + status ramps at 50–950 steps, paired semantic mapping. Novel concepts: hero-stage recipes, icon-kit 5-attribute matching.

### Stage 5: BUILD — assemble the surfaces

**Dashboard / tool / app** (dense, restrained):
1. `/interface-design-init` — establish project `system.md`.
2. Plain Tailwind + shadcn/ui primitives.
3. Pull sparingly from `react-bits` (hero, nav, or data viz only).
4. `responsive-design` for breakpoints.
5. `framer-motion-patterns` for selective motion (max 2–3 animated elements).

**Marketing / landing / hero** (distinctive, animated):
1. `impeccable-design` — generate creative scaffold.
2. `react-bits` — pick ONE animated background + ONE headline treatment + ONE supporting effect.
3. `responsive-design` — mobile-first breakpoints.
4. `market-landing` — CRO section audit (hero → value prop → social proof → CTA → pricing → FAQ).

**Video UI**: `video-ui-patterns` + `remotion-animation`.

**Next.js note** — wrap `react-bits` 3D / shader / face-api components in `'use client'` or `next/dynamic({ ssr: false })`.

### Stage 6: AUDIT — technical quality gates

Run in order. Do not skip.

1. `impeccable-audit` — a11y + perf + theming + responsive + anti-patterns (scored).
2. `baseline-ui` — animation durations sane, type scale enforced, component a11y, layout anti-patterns.
3. `fixing-accessibility` — ARIA, keyboard nav, focus management, contrast (WCAG 2.2 AA minimum).
4. `fixing-motion-performance` — compositor properties, scroll-linked motion, blur budget.
5. `fixing-metadata` (marketing only) — titles, meta desc, OG, canonical, favicon.
6. `/interface-design-audit` — check against project's `system.md`.

Record findings. Fix P0/P1 before ship.

### Stage 7: POLISH — final micro-detail pass

Run `impeccable-polish`:
- Alignment — pixel-perfect component edges.
- Spacing — consistent rhythm, no orphan gaps.
- Consistency — same component renders identically across surfaces.
- Micro-details — hover, focus, disabled, loading skeletons.
- `/interface-design-critique` — one more pass: "where did I default?"

### Stage 8: SHIP — verify + deliver

- **Evidence**: screenshots at desktop + tablet + mobile; Lighthouse; accessibility audit output.
- **Works offline** if applicable (PWA-ready).
- **Reduced motion respected** (`prefers-reduced-motion`).
- **Dark-mode parity** if brand has both.
- **Tests**: visual regression snapshot if tooling exists; smoke flow via `webapp-testing` for critical paths.
- Save patterns back: `"Want me to save these patterns to .interface-design/system.md?"`.

## Typed-clarification (UI-specific)

- `MISSING_INFO`: "I need the brand URL / target audience / primary verb before I proceed."
- `AMBIGUOUS`: "Is this a marketing landing page or an in-app dashboard?"
- `APPROACH_CHOICE`: "Brand-first (Hue) or system-first (ui-design-system)?"
- `RISK_CONFIRM`: "Adding 3 canvas backgrounds on the hero will drop Lighthouse perf below 60. Proceed?"
- `SUGGESTION`: "Consider using `hue` — the brand signals suggest a brand-first flow."

## Guardrails

1. Don't spray components — minimum set. One hero background, one headline treatment, one CTA effect.
2. Don't sacrifice a11y for aesthetics — no ARIA, no primary navigation use.
3. Don't stack heavy canvas backgrounds — each costs GPU budget. Profile before stacking.
4. Don't skip the audit — `impeccable-audit` catches what humans miss.
5. Don't guess at brand — if the user did not specify, ask.
6. Reference, don't copy — Hue examples are inspiration, not drop-in templates.

## Hard rules (inherited from /plan)

1. Understand before building — read existing `system.md`, `CLAUDE.md`, project patterns.
2. Match capabilities — pick the right skill; do not duplicate work.
3. Parallelize independent work (max 3 background subagents).
4. Test everything — visual proof, Lighthouse, a11y audit, responsive screenshots.
5. Simplicity compounds.
6. Evidence, not assertions.
7. Never break main.
8. Demand elegance.
9. Deliver complete work.
10. Route before burning tokens — Qwen for scaffold/explore/cherry-pick; Claude for orchestration + governance.

## Success criteria

A `/planUI` run is complete when:

- [ ] Design brief answered in concrete terms (who / what / feel).
- [ ] Direction stated (palette / depth / surfaces / typography / spacing / motion) with WHY.
- [ ] Tokens exist (Hue-generated, ui-design-system-generated, or inferred + saved to `system.md`).
- [ ] Components built using the minimum set.
- [ ] Audit passed (`impeccable-audit` ≥ threshold, a11y clean, responsive verified).
- [ ] Polish pass ran.
- [ ] Evidence collected (screenshots, Lighthouse, a11y output).
- [ ] Patterns saved back to `system.md` if new ones emerged.
